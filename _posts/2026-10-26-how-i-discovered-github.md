When I started off in software engineering in my first year of uni I didn't actually know much at all about the world of tech. I had no technical background whatsoever and didn't a clue what tools the developers actually used on a day to day basis.

Gradually I started watching videos from various developers and talking to the seniors and other folk in the industry and there was one thing you'd hear over and over again.

Git. GitHub. Git. GitHub. GitHub, over and over.

I started seeing those words in pretty much every developer video I watched. After watching some videos, I became curious. I was wondering what the hell Git and GitHub were and why the hell everyone was talking about them.

That curiosity was the genesis.

I started learning about Git and GitHub and at the same time I switched from Windows to Linux. Looking back that was one of the best periods of my software engineering career as I was looking at Linux, Git and GitHub all at the same time. One thing led to another and I became much more interested in how developers actually work.

## My First Experience with GitHub

My very first experience with GitHub was during a hackathon project and I had absolutely no idea what I was doing at all.

I'd find some commands online, copy them, paste them into the terminal and hope for the best. If I wanted to upload my code I'd copy a command. If I wanted to undo something or revert a change I'd search for the appropriate command and copy that.

Copy. Paste. Copy. Paste. Copy. Paste.

I was essentially a dummy robot going through the motions, following instructions without any real understanding of what was going on underneath the surface. I wasn't actually learning Git at that stage. I was just going through the motions of copying a command from one place and pasting it into another.

But somehow it worked. I managed to get my code up on GitHub and that was my starting point.

## From Copying Commands to Understanding Git

After a while things started to change and I became rather more curious as to what the hell I was actually doing.

What does `git push` actually do? What's the difference between `git fetch` and `git pull`? What is rebasing? How do I undo a change? How does Git track my code? What actually happens when you run those commands?

These questions started to become genuinely interesting to me.

I didn't want to be forever copying commands. I wanted to understand them. So I started spending a lot more time learning the Git commands, learning the Git workflows and understanding version control.

I went on to explore some of the more advanced concepts  and the more I learned the more interested I became. Something that at first had completely baffled me was slowly starting to make sense.

And that sense of having understood something which previously had seemed utterly alien was probably one of the most rewarding aspects of the whole thing.

## Why GitHub Became Part of My Workflow

As I went on to develop projects, GitHub very gradually became part of the way I worked. Whenever I was working on a project, either starting one or working on an existing one, Git and GitHub were part of the process.

I also started to see why version control is so important to software developers. The ability to track changes, experiment with code, work with others and roll back if you make a mistake is a massive advantage.

In my view Git and version control are absolutely among the most useful things ever invented for software development. It's hard to envisage working on any project at all without some form of version control to track your changes and maintain a history of your code.

In truth I just went with GitHub. I was hearing all the time about GitHub, I was learning Git via GitHub and I was using it for my projects. I didn't really know about GitLab or Bitbucket at all. GitHub was the one I discovered first so that was the one I naturally ended up with.

Over time it became more than just a place to upload code. It became part of the way I learned, part of the way I experimented and part of the way I built things.

## I'm Still Learning

I wouldn't call myself a Git expert by any means. I wouldn't even call myself an intermediate user. I'm still very much a beginner, though I do understand the fundamentals, I know what I'm doing in the workflows that I use and I'm still learning as I go on with the various projects I work on.

There's still a hell of a lot I haven't got to and that's absolutely fine with me.

In fact the more I learn about Git the more I find myself wondering. Each new thing you learn about it gives you yet another reason to understand how version control works and how you can use it in your development workflow.

Looking back, learning Git and GitHub was probably one of the best things I did during my  career. It started with a few dev videos, some chat with the seniors and a lot of confusion. Then it was all about copy and paste, lots of questions, lots of experimentation and eventually a much better understanding.

I didn't know it all at the outset and I'm still a long way from being an expert. That's the fascinating thing about learning technology really: you start off somewhere (however ignorant you may be at the time) and you gradually work your way through it.

For me it all started with two words that were everywhere: Git and GitHub.
